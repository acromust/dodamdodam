# 도담도담

가족이 재생 조건을 정해 남긴 5초 음성 메시지를 운전자에게 제때 안전하게 전달하는 앱

도담도담은 차 밖의 가족이 남긴 5초 음성 메시지를 차량이 운전자에게 제때 전달하는 Pleos Connect 앱이다. 가족은 휴대전화 웹에서 메시지를 전달할 순간을 일곱 가지 중 하나로 고르고 5초 음성 메시지를 남기며, 차량은 와이퍼, 기어, 배터리·연료 잔량, 위치 등의 신호로 그 순간이 왔는지를 판단한다. 순간이 오더라도 방향을 바꾸는 중이거나 방향지시등이 켜져 있거나 내비게이션 안내·통화 소리가 나오는 등 운전이 바쁜 상황에서는 알림을 미루고, 그 상황이 끝난 뒤 알림음과 안내 음성을 낸다. 운전자는 핸들 가운데 버튼을 눌러 메시지를 듣고, 누르지 않으면 주차한 뒤 차량 화면에서 듣는다. 정차한 뒤에는 가족을 닮은 캐릭터가 모인 '도담도담 광장'에서 5초 음성이나 이모티콘으로 답장한다. 운전자가 메시지를 들었는지와 차량의 위치는 메시지를 남긴 가족에게 전달되지 않으며, 가족이 받는 것은 운전자가 정차 중에 직접 보낸 답장뿐이다.

대표 장면은 다음과 같다. 남편이 차로 퇴근하는 길에 소나기가 쏟아지자, 아내가 휴대전화로 "비 오니까 천천히 와. 우산 뒷자리에 있으니까 쓰고 들어와."를 '비 올 때'로 남긴다. 차량은 약 3초 안에 메시지를 받고, 남편이 핸들을 꺾는 중이면 기다렸다가 직진이 이어지는 시점에 알림음을 낸다. 남편은 핸들 가운데 버튼을 눌러 메시지를 듣고, 주차한 뒤 답장한다.

## 1. 실행 방법: 서버 없이 예시 메시지로 확인하기

차량 앱은 서버에 연결되지 않은 상태에서도 앱에 내장된 **예시 메시지**로 전체 흐름을 보여 준다.

1. APK를 설치한다: `adb install -r -g apk/도담도담_release.apk` (APK 위치는 8장)
2. 앱을 열고 다음 순서로 첫 설정을 마친다: **[다음]** → 속도·위치 권한 **[허용하기]**(미리 허용되어 있으면 이 단계는 건너뛴다) → 내 이름 → 핸들 가운데 버튼 연습 → 듣는 방식 고르기(기본 "버튼 눌러서 듣기") → **[시작]**
3. 앱이 서버에 연결되지 않고 저장된 메시지도 없으면, 예시 메시지 6개(수진님·지윤님 이름)로 대기한다. 화면과 사람 목록에는 **"체험용 예시"** 라고 표시된다.
4. 아래 "에뮬레이터 조작"에 따라 출발 → 비(와이퍼) → 배터리 부족 → 주차 순으로 조작하면 순간마다 알림음과 예시 메시지가 재생된다.

- 예시 메시지는 들음 기록과 답장을 서버로 보내지 않는다.
- 서버에 연결되면 예시 메시지는 종료되고 실제 메시지로 바뀐다.
- 예시 메시지 확인 중과 개발 빌드에서는 확인하기 쉽도록 판단 시간을 줄인다(주차로 보는 주행 15초, 오래 달림 30초). 실제 기준은 3분, 2시간이다.

## 2. 실행 방법: 서버에 연결해 메시지 남기기

서버 주소: `https://dodamdodam.onrender.com`

1. 차량 앱 메인 화면에서 **[초대 코드 만들기]**를 누른다(연결된 사람이 있으면 **설정** → **사람·초대** → **[초대 코드 만들기]**).
2. 차량 화면에 QR, 주소, 숫자 6자리 코드가 표시된다. 휴대전화 카메라로 QR을 찍거나 `dodamdodam.onrender.com`을 열고 코드를 입력한다. 코드를 입력한 사람만 그 차량에 메시지를 남길 수 있다.
3. 휴대전화에서 처음 접속하면 초대장 **[시작하기]** → 닮은 모습 고르기 → 캐릭터 → 이름 정하고 "(필수) 만 14세 이상이에요" 체크 → **[내 자리 만들기]** 순으로 가입한다.
4. 홈에서 순간(예: 비 올 때)을 고르고 5초 녹음 → 듣기·다시 녹음, 날짜, 반복을 정한 뒤 **[남기기]**를 누른다.
5. AI 음성 검수가 끝나면 차량이 몇 초 안에 메시지를 받는다. 차량 화면 가운데에 "예약된 음성 메시지 N개"가 표시된다.
6. 에뮬레이터에서 출발하고 와이퍼를 10초 넘게 켠다(비 판단).
7. 운전이 바쁘지 않은 시점이 되면 알림음과 함께 "음성 메시지가 도착했습니다. 들으시려면 핸들 가운데 버튼을 눌러 주세요."라는 안내 음성이 나온다. 같은 운행의 두 번째 알림부터는 "음성 메시지가 도착했습니다."만 나온다. 화면에는 핸들 버튼 그림이 함께 표시된다.
8. 안내 뒤 8초 안에 **핸들 가운데 버튼**(또는 화면의 [듣기])을 누르면 메시지가 재생된다. 누르지 않으면 주행 중에는 재생하지 않고, 주차한 뒤 들려준다.
9. 주차(P) 뒤 들은 메시지 화면에서 **[답장]** → 5초 녹음 순으로 답장하면, 휴대전화의 '내 메시지'에 답장이 도착한다.

에뮬레이터 조작 (Pleos 가상 콘솔)
- 기어: P → D로 출발하고, 주행을 마치면 P(주차)
- 속도: 출발 뒤 시속 15km를 한 번 넘겨야 주행 중 알림이 시작된다
- 와이퍼: 켜고 10초 넘게 두면 "비 올 때" 순간이 성립한다
- 조향: 30° 넘게 꺾고 있으면 "잠시 후: 조향 중"으로 기다렸다가 직진 3초 뒤 알린다
- 방향지시등: 주행 중 켜면 꺼진 뒤 3초까지 기다린다
- 배터리 잔량: 15% 아래로 내리면 "배터리 부족할 때" 순간이 성립한다
- 핸들 재생 버튼: `adb shell input keyevent KEYCODE_MEDIA_PLAY_PAUSE`

도움말
- 가상 콘솔 페이지를 연 브라우저 창이 가려지면 신호가 끊길 수 있으므로, 콘솔 창은 화면에 보이게 둔다.
- 답장은 에뮬레이터 마이크 입력이 켜져 있어야 녹음된다(에뮬레이터 확장 설정의 마이크 항목에서 호스트 오디오 입력 사용).
- 휴대전화 웹에서 녹음하려면 서버가 https 주소여야 한다(브라우저 규칙).

## 3. 구현된 기능

차 밖의 가족 (휴대전화 웹, 앱 설치 없음)
- 초대 링크로만 메시지를 남긴다. 운전자는 링크마다 따로 연결을 끊을 수 있다
- 처음 접속할 때 캐릭터를 만든다(닮은 모습 고르기 → 머리·얼굴·옷 바꾸기, three.js 3D 미리보기, 3D를 쓸 수 없으면 2D 그림). 이름과 프로필 사진(선택)을 정한다
- 만 14세 미만 어린이 프로필: 보호자 휴대전화에서 법정대리인 동의를 거쳐 만들고, 어린이는 그 휴대전화에서 메시지를 남긴다
- 날짜: 오늘, 내일, 날짜 고르기, 30일 동안
- 전달 순간 7가지: 차 탈 때, 주차했을 때, 집 근처에 왔을 때(차량 내비게이션에 저장한 집), 고른 장소에 왔을 때(지도에서 고름. 카카오 장소 검색, 사용할 수 없으면 OpenStreetMap 검색), 비 올 때, 오래 달렸을 때, 배터리·연료가 부족할 때(에뮬레이터는 전기차이므로 배터리로 확인)
- 5초 녹음, 반복(한 번만 / 매번)
- 남긴 메시지 다시 녹음·지우기, 답장과 이모티콘 반응 받기, 탈퇴
- 메시지를 남길 계기 알림: 가족이 있는 곳에 다음 날 비 예보가 있으면 전날 저녁 "내일 비가 온대요 / 비 올 때 들려줄 메시지를 남길 수 있어요"를 보낸다(웹 푸시. 실제 휴대전화 도달 여부는 7장의 확인 항목에 포함)

AI 음성 검수
- 욕설·혐오, 놀라게 하는 소리, 운전 중 조작을 요구하는 말을 차량으로 보내지 않는다(Google Gemini API). 판정이 애매하면 보류한 뒤 다시 검수한다. 프로필 사진도 같은 방식으로 확인한다

운전자 (차량 앱)
- 차량 홈 '도담도담 광장': 메시지를 남긴 가족마다 캐릭터가 쿠션에 앉아 있는 3D 장면(Filament)이다. 날씨·밤·문·안전벨트·무드등 같은 차량 신호에 반응하며, 주차(P)에서만 움직인다. 저사양 모드를 지원한다
- 가족이 메시지를 남기면 차량이 몇 초 안에 받는다
- 그날 첫 출발에 예약된 메시지가 있으면 짧은 안내 "예약된 음성 메시지가 있습니다."가 나온다(알림음 없음). 주행 중 메인 화면에는 예약된 메시지 개수만 표시한다
- 전달 시점 조정: 큰 조향, 주행 중 방향지시등, 내비게이션 안내·통화·음성 비서·알람 소리, 주차장을 벗어나는 중에는 알림을 미룬다
- 듣는 방식 3가지: 버튼 눌러서 듣기(기본), 버튼 없이 듣기, 주행 집중 모드(운전 중 알림 끄기 · 주차 후 듣기)
- 핸들 재생 버튼과 화면 위 알림 카드 [듣기]
- 메시지가 재생되는 동안 음악을 잠시 멈췄다가 다시 이어 재생한다
- 주행 중 듣지 못한 메시지를 주차할 때 이어서 들려준다
- 정차 후 답장(5초 녹음)과 이모티콘 반응
- 반복 메시지는 주차 때 [듣기] / [그만 듣기]
- 답장하지 않은 메시지 카드(정차 중 화면)
- 지난 메시지 다시 듣기(보관 기간 안)
- 사람 신고(그 사람의 초대 링크가 끊기고 남은 메시지도 재생되지 않는다)
- 서버 없이 동작하는 예시 메시지
- 차량마다 메시지를 나누어 보관한다(서버 하나를 여러 차량이 써도 섞이지 않는다)

## 4. 안전·개인정보 원칙

- **운전이 바쁘지 않을 때만 알림**: 순간이 와도 바로 재생하지 않는다. 직진이 3초 이상 이어질 때만 알리고, 버튼을 누른 뒤에도 재생 직전에 운전 상황을 한 번 더 확인한다.
- **버튼을 눌러야 재생**: 기본 설정에서는 알림음 뒤 운전자가 버튼을 눌러야 재생된다. "들으시겠어요?"처럼 묻거나 다시 재촉하는 안내는 두지 않는다.
- **주행 중 정보량 제한**: 주행 중 메시지는 5초 이내의 한마디이다. 운전이 바쁜 상황에서는 기다리고, 버튼을 누르지 않으면 주차할 때 들려준다.
- **주행 중 화면 최소화**: 주행 중에는 예약된 메시지 개수와 듣기 버튼만 표시한다. 다시 듣기·답장·설정은 정차 중에만 사용할 수 있다.
- **들음 여부와 위치 비전송**: 차량 신호와 위치 판단은 모두 차량 안에서 처리한다. 메시지를 남긴 가족에게는 운전자가 보낸 답장만 전달된다. 운전자가 앱을 닫거나 그만 듣기를 고른 사실도 메시지를 남긴 가족에게 전달되지 않는다.
- **들은 날짜만 기록**: 같은 메시지를 다시 재생하지 않도록 서버에는 들은 날짜만 남기고 시각은 남기지 않는다.
- **첫 실행 시 고지**: 차량 앱 첫 화면에 서버로 전송되는 정보(내 이름, 답장 목소리·이모티콘, 들은 날짜)와 전송되지 않는 정보(차량 위치, 운전 정보)를 적고, 개인정보 처리방침을 바로 열 수 있게 하였다.
- **보관 기간**: 전달 기간이 끝나고 30일 뒤 서버가 음성 메시지와 답장을 삭제한다. 메시지를 남긴 가족은 언제든 자기 메시지를 지울 수 있으며, 지운 메시지는 차량에서도 곧 빠진다.
- **AI 음성 검수**: 남긴 음성 메시지는 차량으로 보내기 전에 검수한다. 검수 서비스를 사용할 수 없을 때는 음량만 확인하여 먼저 보내고, 이후 다시 검수하여 부적절한 메시지는 차량에서 삭제한다. 만 14세 미만은 보호자가 법정대리인 동의를 한 어린이 프로필로만 메시지를 남긴다.

## 5. 차량 환경에 맞춘 구현

- **안내 음성은 미리 녹음한 파일**: 차량이 들려주는 안내 4가지("음성 메시지가 도착했습니다." 등)는 기기 음성 합성(TTS) 대신 미리 녹음한 파일(`car-app/app/src/main/res/raw/ann_*.m4a`)을 재생한다. 차종이나 기기 설정과 관계없이 늘 같은 목소리, 같은 길이로 안내하기 위함이다. 파일이 없으면 안내 음성은 건너뛰고, 메시지 알림은 알림음만 낸다.
- **주행 중 광장 그리기 중단**: 주행이 시작되면 광장의 캐릭터를 각자 자리의 기본 자세로 멈추고, 장면을 한 번만 그린 뒤 그리기를 멈춘다(`PlazaView.setDriving`). 이에 따라 주행 중 CPU 사용률은 0~0.5%이다(에뮬레이터 실측, 기기 전체 기준, Pleos 기준 5% 미만). 정차하면 다시 움직인다.
- **즉시 수신과 5분 주기 보완**: 차량은 서버에 요청을 걸어 두고 변경이 생길 때까지 기다린다(롱폴링, `/api/changes`. 서버는 변경이 없으면 25초 뒤 응답하고 차량은 다시 요청한다). 메시지가 새로 남겨지거나 삭제되거나 검수가 끝나면 그 자리에서 목록을 다시 받는다. 연결이 끊긴 동안 누락된 변경은 5분마다 목록을 한 번 더 받아 보완한다(`CarService.LIST_REFRESH_MS`).

## 6. 폴더 구성

- `car-app/` 차량 앱(Android, Kotlin). Pleos Connect SDK Vehicle·NaviHelper·FusedLocation, 3D 광장은 Filament.
- `car-app/tools/` 광장 장면·캐릭터·얼굴 그림·안내 녹음을 만드는 스크립트(원본 폴더는 `DODAM_REFS` 환경 변수로 지정하며, 원본은 저장소에 포함하지 않는다)
- `server/` 가족용 휴대전화 웹(`web/`: 화면, 개인정보 처리방침·이용약관·위치정보 이용약관)과 서버(`server.py`), 검수(`moderate.py`), 웹 푸시(`push.py`), 클라우드 보관(`store.py`), `Dockerfile`
- `tests/` 회귀 테스트 도구(`reg.py`)와 결과 기록(`RESULTS.md`)
- `render.yaml` 클라우드 배포 설정(비밀 값은 적지 않는다)

APK 빌드 (JDK 17, Android SDK, Gradle 8 이상 필요)

```
cd car-app
gradle assembleRelease -PapiBase=https://dodamdodam.onrender.com -PshareBase=same -PcarKey=<열쇠>
adb install -r -g app/build/outputs/apk/release/app-release.apk
```

- 개발용은 `assembleDebug`(결과 `app/build/outputs/apk/debug/app-debug.apk`)이다. 개발 빌드만 http 주소(로컬 서버)에 연결되고 로그를 남긴다. release 빌드는 https 서버만 사용하고 로그를 남기지 않는다.

- `-PapiBase`: 차량이 연결하는 서버 주소. 생략하면 로컬에서 실행한 서버(에뮬레이터에서 `http://10.0.2.2:8090`)
- `-PshareBase`: 초대 링크 앞부분 주소. `same`이면 `-PapiBase`와 같고, 생략하면 `http://localhost:8090`
- `-PcarKey`: 서버가 차량 전용 주소를 열쇠로 잠갔을 때 넣는 값. 저장소에는 적지 않고 빌드할 때만 넣는다
- 세 값을 모두 생략하고 빌드하면 서버가 없을 때 바로 예시 메시지로 동작한다.

서버 로컬 실행 (파이썬 3, ffmpeg 필요)

```
cd server
python3 server.py 8090
```

- 웹은 `http://localhost:8090`, 에뮬레이터의 차량 앱은 `http://10.0.2.2:8090`으로 연결한다.
- 선택 환경 변수: `PORT`, `TZ`, `CAR_KEY`, `GEMINI_API_KEY`, `MOD_MODELS`, `MODERATE`, `KAKAO_JS_KEY`, `KAKAO_REST_KEY`, `SUPABASE_URL`, `SUPABASE_KEY`, `SUPABASE_BUCKET`, `VAPID_PUBLIC`, `VAPID_PRIVATE`, `FORECAST`
- 카카오 키가 없으면 지도는 MapLibre + OpenFreeMap(사용할 수 없으면 Leaflet + OpenStreetMap), 장소 검색은 OpenStreetMap(Nominatim·Photon)으로 동작한다.
- 웹 푸시는 `pywebpush`가 설치되어 있을 때만 켜진다.

## 테스트 환경 및 필요한 설정

- Pleos Connect Emulator 2.1.0(Android 14, API 34)과 Pleos Connect Virtual Console을 사용한다. 화면 규격은 2560×1440(160dpi, 가로)이며, Pleos Connect에서 내비게이션과 1:1로 나눈 화면과 도담도담 단독 화면 모두에서 확인하였다. 기어·속도·와이퍼·배터리는 위 '에뮬레이터 조작'에 따라 바꾼다.
- 앱 설치는 `adb install -r -g`(권한을 미리 허용)로 한다. `-g` 없이 설치하면 첫 실행에서 속도·위치·알림 권한을 묻는다.
- 서버: 클라우드(`https://dodamdodam.onrender.com`)로 빌드한 APK는 별도 설정이 필요하지 않다. 시연용 서버는 무료 요금제로 운영하므로 한동안 접속이 없으면 첫 응답이 늦을 수 있으며, 그동안 차량 앱은 예시 메시지로 동작한다.
- 답장 녹음: 에뮬레이터 확장 설정의 마이크 항목에서 호스트 오디오 입력을 켠다.
- 휴대전화 웹: https 주소에서 열어야 녹음된다. 카카오톡 등 앱 안 브라우저로 열면 다른 브라우저로 여는 방법을 안내한다.

## 7. 검증 결과 요약

모든 검증은 Pleos Connect 에뮬레이터(Android 14)와 가상 콘솔, 위 서버에서 수행하였다. 소리 재생 여부는 오디오 상태와 로그로 판정하였다. 자세한 내용은 `tests/RESULTS.md`에 기록하였다.

- 회귀 테스트(11/06, 화면 개편 뒤): 23가지 경우, 확인 항목 57개를 모두 통과하였다. 콘솔이 속도를 천천히 줄여 시간이 빠듯한 2개(주차장 속도, 정차 중 방향지시등)는 한 번 실패한 뒤 다시 실행하여 통과하였다.
- 서버 테스트(11/10, 제출 정리 뒤): `python3 tests/reg.py --server` 확인 항목 209개를 모두 통과하였다(검수를 끈 서버 사본).
- 서버 테스트(11/07, 광장 더미 적용 뒤): `python3 tests/reg.py --server` 확인 항목 63개를 모두 통과하였다(에뮬레이터 없이 서버만).
- 실제 휴대전화 종단 확인(11/03): 아이폰 웹에서 메시지를 남긴 뒤 서버 검수를 포함해 약 3초 뒤 차량에 도착하였고, 와이퍼를 켜고 10초 뒤 알림, 핸들 버튼을 누른 뒤 0.02초에 재생, 주차 후 답장이 휴대전화에 도착하였다. 사설망 안의 https 주소와 로컬 서버로 시험하였으며, 차량 마이크가 꺼져 있어 답장은 샘플 파일로 보냈다.
- 회귀 테스트(11/03): 에뮬레이터·콘솔·서버를 자동으로 조작하여 23가지 경우, 확인 항목 44개를 모두 통과하였다. 버그를 고친 뒤 다시 실행한 44개도 테스트 도구 문제 하나를 고친 뒤 모두 통과하였다.
- 서버 테스트 8개(같은 메시지 두 번 보내기, 끊긴 링크, 비정상 값 등)와 서버 하나에 차량 두 대를 연결한 테스트 6개(서로의 메시지·초대·답장에 영향 없음)를 통과하였다.
- 첫 전수 점검(10/28): 소리, 차량 신호, 앱 생명주기, 서버·웹의 경우 40여 개를 확인하고, 발견한 문제를 고쳤다.
- AI 음성 검수: 시험 문장 7개를 모두 맞게 판정하였다(응원·당부는 통과, 욕설·조작 지시·사이렌·삐 소리는 차단). 실제 목소리 3개로 별도 확인하였다.
- 서버 없이 예시 메시지로 출발 → 비 → 배터리 부족 → 주차까지의 흐름을 확인하였다.
- 성능(에뮬레이터 실측, 기기 전체 기준): 메모리 약 200MB(가족 5명, Pleos 기준 400MB), 주행 중 CPU 0~0.5%(기준 5% 미만), 정차 중 CPU 4~7%(기준 25% 이하).
- 전달 지연 시뮬레이션: 차량 앱의 판정 규칙을 그대로 옮긴 계산 모형에, 공개 주행 자료(NHTSA 차로 변경 연구, EPA 주행 사이클)로 보정한 네 가지 도로 유형의 주행을 0.1초 단위로 재현하고 4만 번(도로 유형 4개 × 1만 번) 계산하였다. 메시지의 74%는 도착 즉시, 93%는 10초 안에 안내되었으며, 미루어진 경우의 평균 대기 시간은 약 9초였다. 주행 중 안내하지 못하고 주차 뒤로 넘어간 경우는 0번이었고, 에뮬레이터 주행 기록과의 안내 시각 차이는 0.02초였다. 실차 주행 기록이 아닌 합성 주행에 기반한 결과이다.

실차·실기기에서 확인할 항목
- 실제 차량에서 들리는 소리와 크기(에뮬레이터 오디오가 꺼져 있음). 메시지 음량은 차량의 '알림' 볼륨을 따른다.
- 차량 마이크로 녹음한 답장(에뮬레이터 마이크에 소리 없음)
- 실제 차량의 핸들 버튼 배치와 차종별 버튼
- 시동을 끌 때(절전) 동작
- 메시지를 남길 계기 알림(웹 푸시)의 실제 휴대전화 도달
- 마지막에 고친 웹 화면(끊긴 링크, 검수 대기, 불러오는 중)의 실제 휴대전화 조작
