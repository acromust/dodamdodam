# 도담도담 기능 테스트 결과 (조립 전 전수 점검, 2026-10-28)

에뮬레이터(Pleos Connect, Android 14, user 빌드) + 콘솔(8088) + 프로토 서버(8090). 다른 앱 소리는 프로브 앱이 같은 용도로 오디오 포커스를 잡고 무음 트랙을 재생해 흉내 냄. 맥에서 소리는 내지 않음(오디오 시스템 상태·로그로 판정).

## 판정
**핵심 고리는 구현 가능(에뮬레이터 실측 통과).** 단 3곳은 피봇, 1곳은 새 설계가 필요.

| 구분 | 내용 |
|---|---|
| 피봇 1 | 음악 '덕킹(작아짐)' → **'잠깐 멈춤'**. 에뮬레이터 차 오디오는 덕킹 신호를 안 씀(`Use hal ducking signals false`), 음악 트랙 감쇄 0dB. 잠깐 멈춤은 음악 앱이 LOSS_TRANSIENT → 끝나면 GAIN으로 확실히 동작 |
| 피봇 2 | **'도착 ○분 전'·'휴게소에서'는 시연 불가.** 에뮬레이터 내비는 차 위치가 안 움직임(NMEA 체크섬 문제, 기존 실측). → 시연 순간은 기어·와이퍼·주행 시간만으로: 차 탈 때 / 비 오면 / 오래 달린 뒤 멈출 때 / 도착(P) |
| 피봇 3 | **'남길 때 알림'은 1차에 웹 푸시·문자 대신 캘린더 반복 알림(.ics)부터.** 앱 없는 웹은 아이폰 푸시에 홈 화면 추가가 필요, 문자·알림톡은 유료·사업자 등록 |
| 새 설계 | **받는 차 연결(초대·인증).** 지금 프로토는 서버 하나 = 차 하나. 운전자별 초대 링크 토큰이 있어야 남이 숨기거나 다른 차로 가지 않음 |

## 논리 구멍 (설계로 막아야 함)
1. **차를 여러 사람이 같이 쓰면** 아빠에게 숨긴 말을 엄마가 들을 수 있다 → Pleos 프로필마다 앱이 따로 돈다는 점을 쓰고, 순간 전에 "○○님께 온 메시지" 대상 확인은 안 함(서프라이즈 유지). 기획서에 "내 프로필에서만" 명시.
2. **동승자가 있을 때 사적인 말이 나옴** → 착석 신호가 되므로 "혼자일 때만" 옵션을 다시 넣을 수 있음.
3. **'도착'은 '오래 달린 뒤 P'** 라서 편의점 정차도 도착으로 본다(실제 기준 5분). 내비 도착 이벤트는 에뮬레이터 확인 불가.
4. **자정을 넘는 운행**: 새 날 메시지는 다음 출발 때 받는다(허용).
5. **목소리 크기는 차 '알림 볼륨'** 을 따른다. 운전자가 알림을 줄이면 같이 작아짐.
6. **초대·인증이 없으면** 링크를 아는 누구나 숨길 수 있다 → 새 설계 필요.

## 에뮬레이터로 확인할 수 없는 것
실제 소리·체감 크기, 실차 덕킹, 차 마이크 답장, 차 위치 이동(도착 ○분 전·휴게소·내비 안내 음성 실제 타이밍), 절전 진입, Pleos 안내 음성의 끝 신호(에뮬레이터에선 안 옴 → 글자 수만큼 기다림), 실제 폰 웹 녹음(HTTPS).

## 정책 회색
부팅 때 스스로 대기 시작(허용·금지 문구 없음), 포그라운드 서비스 specialUse, Vehicle 권한 사전 승인(기어·와이퍼·조향·속도·좌석·공조), 외부 서버 허용 여부, 아이 목소리 보호자 동의. 위치정보는 쓰지 않으므로 위치정보 약관 부담 없음.

## 추가 확인 (같은 날, 사용자 결정 반영)
- 결정: 음악 '잠깐 멈춤' 채택, 초대 링크 만들기 채택, '남길 때 알림'은 최종이 폰 앱이라 문제없음(피봇 3 취소).
- **집 근처·특정 장소 근처: 된다.** Pleos FusedLocation 1.1.3 `addProximityAlert`로 반경 300m 진입(ENTER)·이탈(EXIT) 실시간 수신. 에뮬레이터 `adb emu geo fix`로 위치를 옮기면 앱 위치가 따라감(내비만 안 따라감). 권한 `pleos.car.permission.FUSED_LOCATION`(dangerous, 실행 중 요청). 집 좌표는 내비 '집' 즐겨찾기(NaviHelper getBookmarkInfo), 특정 장소는 남기는 사람이 고른 좌표. 연속 위치 수신은 1초마다 와서 CPU 부담 → 반경 알림만 쓴다. 위치정보 이용약관 제출 필요.
- **긴 재생과 음악:** 60초 동안 포커스를 잡아도 음악 쪽은 LOSS_TRANSIENT(일시정지)만 받고, 반납하면 GAIN으로 돌아옴. 시스템이 음악을 끝내지 않음. 실제 음악 앱이 오래 멈춘 뒤 스스로 재생을 접는지는 앱마다 다름(우리 메시지는 주행 중 5초).
- **정차 중 여러 메시지:** 메시지마다 포커스를 잡았다 놓아 음악이 사이사이 켜졌다 꺼짐 → 처음 안내 한 번("아들, 아내, 엄마 순서로 들려드릴게요") 뒤 포커스를 한 번만 잡고 이어서 재생, 다 끝나면 반납하도록 고침. 음악: 일시정지 1번, 재개 1번 확인.

## 핸들 재생 버튼으로 '듣기' (2026-10-29)
- 방법: 알림음이 울리는 몇 초 동안만 `WheelWindow`가 미디어 세션을 열어 핸들 재생/정지 키를 받는다. 음악 앱 대역은 프로브 앱(media3, 무음 재생). 키는 `adb shell input keyevent KEYCODE_MEDIA_PLAY_PAUSE`.
- 명령: `adb shell am start -n ai.simeodum.car/.MainActivity --es cmd wheel --es sound notif|media|none --es state playing|paused|none --es sec 8` (`--es sound close`로 닫기)
- **된다 (소리 notif + 상태 none 또는 paused):** 창이 열린 동안 키가 우리 앱으로 옴. 창이 닫히면 버튼 대상이 음악 앱으로 돌아가고, 음악도 다시 재생됨. 음악이 없을 때도 받음. 8초 자동 닫힘 뒤 키는 우리 앱에 안 옴.
- **안 됨 (상태 playing):** 시스템 미디어 앱이 우리를 '지금 음악 앱'으로 바꾸면서 원래 음악을 일시정지시키고, 창을 닫은 뒤엔 버튼 대상이 비어(null) 핸들 버튼이 아무 데도 안 감 → 쓰면 안 됨.
- **소리 없이 세션만:** 키가 음악 앱으로 감(우리 앱이 소리를 내는 중이어야 버튼이 옴).
- 못 본 것: 실제 차 핸들 버튼 배치·차종별 키 코드, 다음 곡 키(일부러 안 씀).
- 두 번 누르기도 시험해서 됐지만(1.2초 안 두 번), 사용자 결정으로 한 번 누르기로 감(10/29).

## 실용 순간 신호 (2026-10-29)
- 명령: `--es cmd energytest`. 콘솔: `POST /vehicle/ev-battery?field=soc&value=14`, `?field=charge_port_open&value=true`, `POST /vehicle/lights?feature=headlamp_mode&value=LowBeam`
- **배터리 잔량: 된다.** 100% → 14% 바뀌자마자 콜백(EvBattery.registerEvBatteryStateOfCharge, 권한 CAR_ENERGY).
- **충전구 열림: 된다.** true/false 콜백(registerEvChargePortOpen).
- **전조등: 된다.** ON/OFF 콜백(Light.registerLowBeamLightState, 권한 CAR_LIGHTS). 단 오토라이트는 터널에서도 켜져서 '밤' 판단엔 시각을 같이 써야 함.
- 기름(%)은 API(Fuel.registerFuelPercent)는 있지만 에뮬레이터 차가 전기차라 확인 못 함.
